# SFTP 首版约定

用户确认：目录同步、远程编辑暂不做；上传和下载均必须支持断点续传。性能、稳定性和流畅度优先。

- Ubuntu 使用原生 GTK 文件栏：右侧可收起、路径导航、虚拟行绘制的文件列表、上传/下载、新建目录、重命名、删除空目录/文件及传输队列。沿用现有配色、字体和认证，不改变终端 PTY 路径。
- 系统 OpenSSH 的 `sftp` 子系统使用独立标准输入/输出管道和真实 SFTP v3 协议，不解析命令行文件列表，不启动 shell 执行文件操作。继续复用 SSH 别名、ProxyJump、指纹确认和系统凭据库。
- 文件浏览按需连接；收起后关闭浏览连接。传输独立于终端标签和文件栏，默认最多同时两个文件，队列上限 1,024 条。目录每批 128 条，每目录上限 50,000 项，通过有界队列交给主线程；文件内容不进入 GUI。
- Windows 和 Ubuntu 可使用「上传文件夹」选择目录，或将文件和目录一起拖入文件栏。上传保留嵌套结构和空目录，普通文件逐个加入原有续传队列。同名真实目录合并，同名普通文件由用户决定是否覆盖，链接和类型冲突的项目跳过。扫描超过 8,192 项、嵌套超过 64 层或超出队列剩余名额时，会在创建远程目录前报错。
- 下载使用最多 32 个并行读取请求，每块最多 64 KiB；上传每批最多 8 个 64 KiB 写入请求，全部确认并释放克隆句柄后再保存进度，最终显式关闭文件后发布。缓冲区大小不随文件大小增加。进度约每 200 ms 一次，阶段结束立即通知，检查点最多每 500 ms 一次，通常每 2 秒保存。
- 传输先写入目标目录中的独立 `.hshell-<随机任务编号>.part`，记录原始源文件大小/修改时间及确认进度；本地检查点原子写入并刷盘，记录无密码。暂停、网络故障、退出或重启均保留任务，恢复需用户点击继续，不静默重新登录。
- 恢复时重新确认源文件身份，并逐字节校验已传前缀，再从确认断点继续；只凭大小不足以判定可续传。校验在后台流水线进行，UI 显示独立的校验阶段。标准 SFTP 不提供通用服务端校验和，完整前缀核对需要重新读取对应远端数据；不以抽样校验替代一致性。
- 完成后确认源文件未改变，刷盘后发布最终文件。默认不覆盖；用户明确选择替换时使用原子重命名。服务器不支持相应原子操作时保留临时文件并明确报错，不先删除旧目标。
- 传输 30 秒无响应转为可恢复错误；用户暂停和应用退出可取消阻塞中的网络操作。连接子进程必须被回收，SFTP 错误不终止终端。
- Ubuntu 22/24 的既有验证包含真实 OpenSSH SFTP、大文件 SHA256 往返、暂停和新进程恢复、连接中断、源文件变化/部分文件篡改拒绝、覆盖与错误路径、大目录交互和终端同时输入/滚动。Windows 11 已使用系统 OpenSSH 和回环 Paramiko 服务端验证 32 MiB 文件跨进程双向续传、前缀校验、SHA256 及中文目录操作。

界面只有读取目录时保留短周期批次调度；传输进度由后台事件唤醒，空闲无轮询。窗口宽度小于 1050 像素时打开文件栏会收起主机栏；窄窗口重新打开主机栏会收起文件栏，传输继续。移除未完成任务前会显示临时文件路径并确认，保留临时文件供用户按需清理，不静默删除远端数据。

首版边界：下载仅支持普通文件，暂不支持递归下载目录；任务路径需要可用 UTF-8 表示；Windows SFTP 文件栏和远程 Unix 路径适配已加入，运行验收状态见 [Windows 客户端](windows.md)。断点校验可识别源内容变化或部分文件损坏，遇到不一致会停止并要求新建任务。源文件应在传输期间保持稳定；服务器支持 fsync 扩展时额外请求刷盘。
